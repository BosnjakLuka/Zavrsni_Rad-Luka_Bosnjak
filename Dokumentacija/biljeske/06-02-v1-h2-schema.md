# 6.2 — Kompletna V1 H2 shema

**Datum:** 2026-08-25

**Status:** IMPLEMENTIRANO / TESTIRANO / NIJE TESTIRANO

## Cilj

Definirati kompletnu početnu relacijsku shemu za potvrđeni V1 model i dodati integration test koji je izvršava na čistoj in-memory H2 bazi.

## Promijenjene datoteke

- `src/main/resources/db/schema.sql` — dodane V1 tablice, ključevi, potvrđena ograničenja i seed uloga.
- `src/test/java/hr/lukabosnjak/config/DatabaseSchemaIntegrationTest.java` — dodan integration test izvršavanja sheme i provjere tablica/seeda.
- `Dokumentacija/biljeske/00_indeks.md` — evidentiran milestone 6.2.
- `Dokumentacija/biljeske/06-02-v1-h2-schema.md` — dokumentirana stvarna implementacija i status provjere.

## Stvarna implementacija

`schema.sql` kreira tablice `ROLE`, `APP_USER`, `MATERIAL_TYPE`, `CNC_MACHINE`, `TOOL`, `MATERIAL_SHEET`, `MACHINING_PARAMETERS`, `SHAPE` i `MACHINING_JOB`. Svi primarni ključevi koriste `BIGINT GENERATED BY DEFAULT AS IDENTITY`. Dodani su potvrđeni strani ključevi, jedinstvenost broja alata unutar stroja, tri V1 snapshot UNIQUE ograničenja i provjera pozitivne količine. Enum vrijednosti spremaju se kao `VARCHAR`, a G-kod kao `CLOB`.

Minimalni seed dodaje samo uloge `USER` i `ADMIN`. Ne stvara korisnički račun ni lozinku jer prvi administrator prema odluci 6.1 nastaje kroz budući first-run setup.

Integration test otvara novu in-memory vezu, učitava `/db/schema.sql` pomoću H2 `RunScript`, preko JDBC metadata provjerava točan skup devet tablica, potvrđuje da tablica `USER` ne postoji te provjerava seedane uloge i prazan `APP_USER`.

## Razlog odabranog rješenja

Jedna eksplicitna classpath SQL skripta čini početnu shemu preglednom i ponovno uporabljivom u testu i budućem initializeru. Standardna H2 identity sintaksa izbjegava legacy prečace. SQL ograničenja pokrivaju strukturni integritet, dok složenija poslovna pravila ostaju u validation/service sloju.

## Arhitektonska povezanost

Shema pripada persistence infrastrukturi i nije povezana s JavaFX controllerom. Test koristi postojeći `DatabaseConfig` factory i kratkoživuću vezu zatvorenu pomoću try-with-resources. Provjera pripada li alat odabranom stroju ostaje buduća poslovna validacija i nije duplicirana SQL ograničenjem.

## Važne odluke i ograničenja

- SQL tablica korisnika zove se `APP_USER`; `ROLE` je quoted identifier zbog sigurnog razlikovanja od H2 SQL pojma.
- `safe_z` postoji samo u `MACHINING_PARAMETERS`.
- `g_code` ostaje jedan `CLOB` u `MACHINING_JOB` za Iteraciju 1.
- Snapshot tablice ne mogu biti povezane s više jobova zbog UNIQUE ograničenja na odgovarajućim FK-ovima.
- Nisu dodani cascade delete, geometrijski CHECK-ovi, repositoryji, initializer ni autentikacijska logika.

## Build i testiranje

### Izvršene naredbe

```text
Get-ChildItem -Force -Name mvnw,mvnw.cmd,.mvn -ErrorAction SilentlyContinue
Get-Command mvn -ErrorAction SilentlyContinue
$schemaJava = 'C:\Program Files\JetBrains\IntelliJ IDEA 2026.2.1\jbr\bin\java.exe'
$schemaH2Jar = Join-Path $env:USERPROFILE '.m2\repository\com\h2database\h2\2.4.240\h2-2.4.240.jar'
& $schemaJava -cp $schemaH2Jar org.h2.tools.RunScript -url 'jdbc:h2:mem:schema-cli-check-repeat' -user sa -script 'src/main/resources/db/schema.sql'
```

### Stvarni rezultat

Maven Wrapper nije pronađen, a globalna naredba `mvn` nije dostupna u izvršnom okruženju. Cijeli `schema.sql` uspješno je izvršen službenim H2 2.4.240 `RunScript` alatom nad čistom in-memory bazom; naredba je završila s izlaznim kodom 0 i bez SQL pogreške. Time su runtime provjereni sintaksa, redoslijed kreiranja tablica, strani ključevi i seed naredbe. JUnit integration test nije izvršen i nema tvrdnje da Maven build ili test prolaze.

### Što nije testirano

Nisu izvršene JUnit tvrdnje koje preko metadata provjeravaju točan skup tablica, seedane uloge i prazan `APP_USER`. Nisu zasebnim negativnim insert scenarijima testirani UNIQUE i CHECK prekršaji. Shema nije pokrenuta nad file-based aplikacijskom bazom. Autentikacija i fizički CNC stroj nisu povezani s ovim testom.

## Kandidati za isječke koda

### Kandidat: V1 snapshot i referencijalna ograničenja

**Datoteka:** `src/main/resources/db/schema.sql`

**Klasa/metoda:** nije primjenjivo — definicija tablice `MACHINING_JOB`

**Zašto je važan:** Prikazuje razliku između dijeljenih referenci i 1:1 snapshot podataka jednog CNC posla.

**Moguće poglavlje:** Relacijski model i integritet podataka

```sql
CONSTRAINT uq_machining_job_material_sheet UNIQUE (material_sheet_id),
CONSTRAINT uq_machining_job_parameters UNIQUE (machining_parameters_id),
CONSTRAINT uq_machining_job_shape UNIQUE (shape_id),
CONSTRAINT chk_machining_job_quantity CHECK (quantity > 0)
```

**Ideja opisa u radu:** Jedinstvenost snapshot FK-ova sprječava da različiti poslovi dijele promjenjive podatke ploče, parametara ili oblika, dok CHECK čuva samo jednostavnu strukturnu invarijantu količine.

### Kandidat: Izvršavanje stvarne sheme u integration testu

**Datoteka:** `src/test/java/hr/lukabosnjak/config/DatabaseSchemaIntegrationTest.java`

**Klasa/metoda:** `DatabaseSchemaIntegrationTest#createsCompleteV1SchemaAndSeedsRoles`

**Zašto je važan:** Dokazuje da test koristi istu classpath SQL skriptu koja je namijenjena aplikacijskoj inicijalizaciji.

**Moguće poglavlje:** Testiranje persistence infrastrukture

```java
try (Connection connection = DatabaseConfig.getConnection(TEST_JDBC_URL)) {
    executeSchema(connection);
    Set<String> actualTables = readPublicTableNames(connection);
    assertEquals(EXPECTED_TABLES, actualTables);
}
```

**Ideja opisa u radu:** Čista in-memory baza izolira test i omogućuje provjeru da je cijela V1 shema izvršiva bez stvaranja lokalnih datoteka.
